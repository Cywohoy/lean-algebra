# 상호작용 미리보기

공개 문서는 [GitHub Pages](https://cywohoy.github.io/lean-algebra/)에서 읽을 수 있다.
단계 보기와 코드 복사는 실행 환경을 불러오지 않아도 동작한다.
공개 사이트의 `풀기`는 브라우저 안에서 Lean 4.35와 Ample을 실행하며 코드를 서버로 보내지 않는다.
처음 실행할 때 최대 약 300 MB를 내려받으므로 데스크톱 환경과 안정적인 연결을 권한다.
로컬 미리보기도 같은 WASM 실행 환경을 사용하며 현재 자동완성은 제공하지 않는다.

`interactive-preview.bat`를 실행하면 `http://127.0.0.1:8001/`에서 교재를 열 수 있다.
일반 미리보기인 `preview.bat`도 같은 기능을 제공하며 주소는 기존의 `8000`번 포트를 사용한다.
이미 문서를 생성했다면 `interactive-preview.bat -SkipBuild`로 실행할 수 있다.
Python 3와 프로젝트의 Lean 도구가 필요하며 별도의 Python 패키지는 설치하지 않는다.

증명이 있는 코드에는 모서리에 `단계`를 항상 표시한다. 코드의 전술을 눌러도 단계를 열 수 있다.
코드 박스에 포인터를 올리거나 키보드로 접근하면 모서리에 작은 복사 아이콘이 나타난다.
아이콘을 누르면 바로 복사하며 확인 문구는 버튼 아래에 잠깐 표시한다. 버튼용 별도 줄은 두지 않는다.

- 증명 코드를 누르면 단계 창이 열리며, 전술을 누르면 그 단계의 가정과 목표가 표시된다. `단계`로 창을 접거나 다시 열 수 있고, 이전·다음 버튼으로 이동할 수도 있다. 정리 이름의 링크는 원래대로 정의가 있는 곳으로 이동한다.
- `풀기`: 풀이 화면을 열거나 입력을 잠시 멈추면 자동으로 Lean에 전달한다. `검사` 또는 `Ctrl+Enter`로 즉시 검사할 수도 있다. 커서를 옮기면 그 위치의 가정과 목표가 표시되며, 증명의 빈 줄에서는 앞선 단계까지의 상태를 볼 수 있다.

- 몫 원소의 겹대괄호는 `\[[`, `\]]` 뒤에 `Tab`을 눌러 입력한다. `\[[]]` 뒤에 `Tab`을 누르면 `⟦⟧`를 함께 넣고 커서를 괄호 안에 둔다.
- 아직 풀지 않은 목표와 `sorry`는 `증명 중`으로 표시하고, 목표 창에서 이어서 확인한다. 실제 구문 오류나 타입 오류는 오류 목록에 남긴다.
- `초기화`: 편집 중인 코드를 교재에 실린 원래 코드로 되돌린다.
- 힌트와 풀이의 제목을 누르면 내용을 펼치거나 접을 수 있다. 현재 입문부의 연습문제 네 개에는 풀이가 있으며 기존 힌트도 접어서 표시한다.

## 연습문제 전용 화면

‘증명의 구성과 사용’ 단원의 연습문제 8개에는 `풀기`를 제공한다.
본문에서는 문제 제목 옆에 큰 `풀기` 버튼을 두고 지문과 코드를 하나의 영역으로 묶는다.
연습문제에는 별도 `편집` 버튼을 두지 않으며 코드 모서리에는 바로 복사되는 작은 아이콘만 둔다.
풀이 화면에서는 문제 설명과 정리의 선언을 위에 두고 증명과 가정·목표를 나란히 표시하며 좁은 화면에서는 아래로 배치한다.
기본 입력란에는 `by` 뒤의 증명만 표시하며 첫 전술은 맨 왼쪽에서 시작한다.
Lean에 전달할 때 필요한 첫 들여쓰기는 편집기가 붙인다. 한 문제에 두 정리가 있으면 `(1)`, `(2)`로 전환하며
두 증명을 함께 검사하므로 앞의 결과를 다음 증명에 사용할 수 있다.
`전체 코드`에서는 선언을 수정하거나 보조 정의를 추가할 수 있다.
원래 선언을 유지한 채 모든 증명을 완성하면 `풀이 완료`를 표시하고,
선언을 바꾼 코드의 검사 성공은 `코드 검사 통과`로 구별한다.
`본문으로` 또는 `Esc`로 닫아도 풀이를 보존한다.
`풀이 내려받기`는 필요한 앞선 문맥을 포함한 `.lean` 파일을 저장한다.

수정한 코드는 브라우저의 로컬 저장소에 저장한다. `Exercises/`의 개인 풀이 파일과는 별도로 관리하며,
이곳에서 수정한 코드를 개인 풀이 파일로 옮기려면 `복사` 또는 `풀이 내려받기`를 사용한다.
전체 코드에서 선언을 수정하면 검사 성공도 수정한 선언에 대한 결과이다.
이 경우 원래 문제의 풀이 완료와 구별하여 표시한다.

## 교재에 새 예제와 풀이 추가

`savedLean` 블록에는 증명 단계 보기와 코드 복사가 연결된다.
현재 풀이 편집기는 `Proofs.lean`의 연습문제에만 연결한다.
각 예제의 실행 환경에는 같은 파일에서 그 예제보다 앞에 있는, 본문에 유지되는 코드만 들어간다.
`-show`로 숨긴 정의와 기호 연결도 포함하며 `-keep`인 연습문제는 포함하지 않는다.
일반 `lean` 블록은 실행 대상에 포함하지 않는다.

완성되지 않은 시도나 풀이처럼 예제 코드 파일로 내보내지 않을 코드는 다음과 같이 적는다.

````
```tryLean +error -keep
example (n : Nat) : 0 + n = n := by
  rfl
```
````

`tryLean`도 문서를 생성할 때 Lean으로 검사한다. `+error`는 오류가 발생해야 하는 예제에만 붙인다.
힌트와 풀이에는 각각 `:::hint`, `:::solution`을 사용한다.

````
:::solution
풀이의 설명을 적는다.

```tryLean -keep
example (P : Prop) : P → P := by
  intro h
  exact h
```
:::
````

인쇄용 출력에서는 조작 버튼을 제외하고 원래 코드와 힌트·풀이의 내용을 출력한다.
웹 기능을 수정한 것만으로 PDF를 다시 만들지는 않는다.

## 구성과 운영 범위

`AlgebraBook/Meta/Lean.lean`은 원래 코드에 웹용 메타데이터를 붙인다.
`AlgebraBook/Meta/Playground.lean`은 예제별 코드와 앞선 문맥을 `playground/`에 내보낸다.
웹 화면의 동작과 모양은 `assets/web/reader.js`, `reader.css`에 있다.

`serve.py`는 `_out/pages/`의 정적 파일만 제공한다. 로컬 실행 API나 Lean 언어 서버를 시작하지 않는다.
`interactive-preview.ps1`은 문서 생성 후 `prepare_pages.py`로 고정된 WASM 실행 파일을 준비한다.
공개 사이트와 로컬의 모든 예제·연습문제는 같은 Worker에서 검사하며 코드를 서버로 보내지 않는다.
`lean_rpc.py`는 개발용 비교 검사에만 남겨 두며 독자용 미리보기에서는 사용하지 않는다.

공개 사이트에서는 `assets/web/wasm-reader.js`가 같은 편집 화면을 WASM Worker에 연결한다.
실행 환경은 `web/wasm-runtime.json`에 고정한 배포 파일에서 가져오며
사이트를 만들 때 SHA-256을 검사한다. `scripts/prepare_pages.py --download-wasm`은
그 실행 파일과 예제의 문맥을 함께 준비한다. 교재 전용 가져오기 경로는 Ample 경로로 바꾸고
입문부에서 필요한 정의는 앞선 문맥에 포함한다. 실행 파일은 편집기를 처음 열 때만 불러온다.
브라우저의 저장소에 남긴 편집 내용은 첫 실행을 위한 새로고침 뒤에도 유지한다.
[`experiments/wasm/`](../experiments/wasm/README.md)에 도구 모음의 빌드·검사 절차를 기록했다.

`node tests/BrowserReader.Tests.cjs`는 실제 공개 편집 화면을 정적 서버만으로 검사한다.
`BOOK_URL`을 지정하면 배포된 사이트에서도 같은 검사를 실행할 수 있다.

검사는 다음과 같이 실행한다.

```powershell
python tests/Playground.Tests.py
```

브라우저 검사는 `tests/InteractiveReader.Tests.cjs`를 사용하며 실행할 서버 주소는 `BOOK_URL`로 지정할 수 있다.
